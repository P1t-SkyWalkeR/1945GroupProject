# UST Course Vibe Match：数据清洗与特征抽取方法论

> 本文档记录项目的方法选择、理由和已达成的决定，供组员撰写最终报告时参考。
> 本文档用中文；repo 中其他所有内容（代码、标注指南、数据表、报告草稿）一律用英文。
> 最后更新：2026-11-23

---

## 1. 目标

从 ust.space 的课程评论中，为每个 **「课程 + 老师」** 组合抽取 13 个维度的结构化画像，作为后续推荐系统的输入。

| 维度 | 提取内容 | 中文取值 | 数据文件中的英文编码 |
|---|---|---|---|
| 课程主题 | 课程主要讲什么，用于兴趣匹配 | 主题类别 + 关键词，可多选 | `topic_categories`, `topic_keywords` |
| 记忆与背诵需求 | 是否需要记忆概念、细节或大量材料 | 低／中／高／未知 | `memorization`: low / medium / high / unknown |
| 逻辑分析与问题解决需求 | 是否需要推理、分析、计算或编程 | 低／中／高／未知 | `analytical`: low / medium / high / unknown |
| 背景知识要求 | 零基础能否跟上，什么背景有帮助 | 零基础友好／有背景更有利／较依赖背景／未知 | `background`: beginner_friendly / background_helpful / background_dependent / unknown |
| 总体工作量 | 对整门课时间和精力投入的评价 | 低／中／高／有条件或混合／未知 | `workload`: low / medium / high / conditional_mixed / unknown |
| 阅读负担 | 阅读的数量、频率、是否需要认真完成 | 低／中／高／未知 | `reading`: low / medium / high / unknown |
| 写作负担 | essay、report 等写作任务的数量和篇幅 | 低／中／高／未知 | `writing`: low / medium / high / unknown |
| 小组合作要求 | 是否需要合作，是否允许个人完成 | 无／有／可选／未知 | `group_work`: none / required / optional / unknown |
| 课堂发言要求 | 回答问题、讨论、被点名、发言计分 | 无／自愿／要求或计分／未知 | `participation`: none / voluntary / required_or_graded / unknown |
| 教学讲解清晰度 | 讲解、组织和材料是否容易理解 | 清晰／一般或混合／不清晰／未知 | `teaching_clarity`: clear / mixed / unclear / unknown |
| 考核难度 | 作业、小测、考试是否难以完成 | 低／中／高／不同考核有差异／未知 | `assessment_difficulty`: low / medium / high / varies / unknown |
| 评分宽松程度 | 对评分严格程度的明确评价 | 宽松／一般或混合／严格／未知 | `grading_leniency`: lenient / mixed / strict / unknown |
| Recording | 是否提供课堂录播 | 有／无／部分提供／未知 | `recording`: yes / no / partial / unknown |

每个维度的具体判定标准见 [labeling_guide.md](labeling_guide.md)（英文）。

## 2. 数据概况

- 来源：`reviews_2023-2026.csv`（ust.space 公开评论）
- 规模：3070 条评论，150 门课程，2023-24 Fall 至 2026-27 Fall，共 13 个学期
- 文本列（四列都使用）：`comment_content`、`comment_teaching`、`comment_grading`、`comment_workload`
- 结构化列：`rating_*`（4 项评分）以及 `has_midterm`、`has_final`、`has_quiz`、`has_assignment`、`has_essay`、`has_project`、`has_attendance`、`has_reading`、`has_presentation`
- 语言：大部分为英文，502 条含中文
- 老师字段：554 条缺失，155 条为多位老师合教
- `hash` 无重复

**范围决定**：150 门课程全部处理，不局限于 proposal 中写的 30–40 门。报告中需要说明这一改动。

## 3. 方法选择：为什么不是「全部用课上的分类器」

### 3.1 最初方案及其问题

最初方案是：人工标注约 400 条评论，再用 BoW / Word2Vec + Perceptron / KNN / MLP 训练，预测其余评论。复盘后发现以下问题：

1. **训练标签本身由 LLM 生成**：用 400 条 LLM 标签训练分类器、再让分类器预测其余 2600 条，结果基本只会比让 LLM 直接读这 2600 条更差。分类器在这里的作用是「展示方法」，而不是「得到准确数据」。
2. **样本量是人为压缩的**：在全部 3070 条评论中，关键词粗略统计显示各维度都有数百条证据（记忆约 600、逻辑约 1250、背景约 480、阅读约 520、写作约 740、工作量约 1770、Recording 约 760）。之前所说的「正例太少」只是 400 条抽样造成的。
3. **部分模型组合不合适**：
   - BoW 向量维度高且稀疏，在这种向量上用 KNN 计算距离效果很差
   - 在 3000 条评论上自己训练 Word2Vec，语料太少
   - 课程主题用 K-means 聚类评论不合理，因为评论多数讨论的是工作量和老师，很少讲内容

### 3.2 最终方案：分工使用

| 方法 | 对应课件 | 用途 | 是否进入最终画像 |
|---|---|---|---|
| LLM 结构化抽取 | L12 GenAI、L14 LLM | 对全部 3070 条评论抽取 13 个维度，并附原文证据 | ✅ 主要来源 |
| 关键词规则 | L3 | 对小组合作、课堂发言、Recording、写作类型做交叉核对 | 只用于核对和标记冲突 |
| BoW / Word2Vec + Perceptron / KNN / MLP | L5、L6、L7、L10 | 对比实验：传统模型能多大程度复现 LLM 的判断 | ❌ 只作为实验结论 |
| K-means（可选） | L7 | 对课程主题关键词向量聚类，做「相似课程」推荐 | 可选扩展 |

**理由**：
- 数据质量：最终数据来自能读懂语境的模型，每个结论都可以追溯到原文
- 课程覆盖：L3、L5–L7、L10、L12/L14 都用到了，并且每个方法都放在适合它的位置
- 可评估：传统模型的对比实验能为报告 Section 6 提供 macro-F1、混淆矩阵和误差分析

## 4. 处理流程

### 步骤 1：预处理（L3）

- 去掉 HTML 标签和实体，如 `<br />`、`&#039;`
- 按 `hash` 去重（当前无重复，保留此检查）
- **隐私**：删除 `author` 列；`is_author` 列不进入输出
- **隐私（2026-11-24 补充）**：评论正文中评论者自己留下的个人邮箱替换为 `[email removed]`（全部数据中只有 1 处）；学校教职员的 `ust.hk` 邮箱是公开的联系方式，予以保留。原始 CSV 含评论者用户名，不放进代码仓库
- 缺失老师：先尝试从正文中识别授课老师（见第 10 节决定记录），识别不到的记为 `Unknown instructor`
- 合教：拆分成多行，每位老师各一行，记入各自的「课程 + 老师」组；同时保留原始的老师组合字段，方便追溯
- 分词（仅用于传统模型实验）：小写化；把 `n't` 统一成 `not`；保留否定词 `not`、`no`、`never`、`without`；中文字符按单字切分作为 token
- 结构化字段原样保留，作为独立特征，不和文本抽取结果合并

### 步骤 2：LLM 抽取（全部 3070 条）

- 输入：一条评论的四列文本，加上课程代码和课程名
- 输出：13 个维度的标签；每个非 `unknown` 的标签必须附一句原文证据（evidence quote）
- 原则：
  - **评论没有提到 ≠ 没有**。没提到的维度一律标 `unknown`，不能推断为 `none` 或 `low`
  - 只依据评论文本，不使用结构化字段，避免两者混在一起
  - 评论者对自己经历的描述（如「我零基础也跟得上」）可以作为证据
- 执行方式：分批交给子 agent 并行处理，所有批次使用同一份标注指南，每批抽样复核以保证批次之间一致

### 步骤 3：规则交叉核对

对事实性维度（`group_work`、`participation`、`recording`、`writing`）用关键词规则再抽取一次：
- 与 LLM 结果一致：可信度高
- 不一致：列入复核清单，逐条人工检查

报告中写明一致率。

**执行结果（2026-11-24，[src/rule_check.py](../src/rule_check.py)）**：

| 维度 | 规则标出 | LLM 标出 | 两边都标 | 一致率 | Cohen's κ |
|---|---|---|---|---|---|
| 小组合作 | 402 | 505 | 392 | 93.6% | 0.57 |
| 课堂发言 | 229 | 423 | 158 | 88.0% | 0.40 |
| 录播 | 281 | 457 | 265 | 88.3% | 0.65 |
| 写作 | 308 | 475 | 203 | 70.0% | 0.33 |

- **不一致的 139 条逐条人工判定**，结果存在 `cleaned/review/rule_adjudication.csv`：
  - 规则错 123 条
  - 两种都说得通 13 条：主要是合教课程里两位老师做法不同，以及发言换 coupon 是否算计分
  - LLM 错 3 条：辩论计分却标成「自愿发言」；两处写作量偏高。已写入 `overrides_rulecheck.json` 修正
- **规则错的典型情况**：
  - 「可以一个人或两人一组」被规则当成必须小组
  - 「两篇短 essay」被规则当成写作量大
  - 「no lecture videos」这种否定没被识别
  - 「all MC」只是在说考试题型，被规则当成没有写作任务
- **反方向**（规则标出、LLM 为 unknown）抽查了 48 条，几乎都是规则误判：例如「attendance is not recorded」、iPRS 计分，只有一两条是 LLM 漏标。
- **结论**：在这四个事实性维度上，LLM 的错误率约为 3/1018 条重叠标签，另有约 1% 有争议；关键词规则精度明显更低。κ 不高，主要是规则的问题，不说明 LLM 标签不可靠。报告中应如实写明，规则只是交叉核对的工具，不作为正确答案。
- **注意**：规则是第一版，没有根据这些不一致去调整。如果事后调规则，一致率会虚高。

### 步骤 4：传统模型对比实验

- 训练标签：步骤 2 得到的 LLM 标签，覆盖所有有序维度
- 文本表示：BoW；平均预训练 Word2Vec / GloVe 词向量（优先使用下载的预训练向量）
- 分类器：Perceptron（baseline）、KNN、MLP，共 2 × 3 = 6 种组合，另加多数类 baseline
- 数据切分：按课程分组（GroupKFold），同一门课的评论不能同时出现在训练集和测试集
- 指标：macro-F1、accuracy、每类 precision / recall、混淆矩阵
- 词表、缩放等预处理只在训练折上拟合，避免数据泄漏
- **注意**：这一步衡量的是「传统模型和 LLM 的一致程度」，不是「和真实情况的一致程度」。后者依赖第 6 节的人工抽检

**执行结果（2026-11-24，[src/classic_models.py](../src/classic_models.py)，结果在 `cleaned/experiments/`）**：
- **设置**：
  - 词向量用 GloVe 100 维（gensim-data 的 `glove-wiki-gigaword-100`），平均每条评论有 10.9% 的 token 不在词表里，主要是中文
  - KNN 取 k = 15，距离加权；BoW 上用余弦距离
  - MLP 一个隐藏层，64 个单元，early stopping
  - Perceptron 用 `class_weight="balanced"`
- **任务**：每个维度做两个：
  - full：连 unknown 一起预测
  - level：只在 LLM 给了标签的评论上预测等级
- **macro-F1（6 种组合的平均）**：

  | 组合 | full | level |
  |---|---|---|
  | BoW + Perceptron | 0.39 | 0.43 |
  | BoW + MLP | 0.30 | 0.35 |
  | GloVe + Perceptron | 0.28 | 0.37 |
  | GloVe + MLP | 0.26 | 0.32 |
  | BoW + KNN | 0.26 | 0.32 |
  | GloVe + KNN | 0.26 | 0.32 |
  | 多数类基线（各维度范围） | 0.12–0.24 | 0.14–0.31 |

- **各维度最好成绩**：几乎都来自 BoW + Perceptron。
  - full 任务：记忆 0.47 最高，考核难度 0.31 最低
  - level 任务：记忆 0.53、讲解清晰度 0.51、评分宽松度 0.50 较高，工作量 0.39、考核难度 0.36 较低
- **主要结论**：
  1. 传统模型都高于基线，说明文本里确实有可学的信号；但离 LLM 的判断差得很远，macro-F1 最多约 0.5。
  2. 准确率会误导：很多维度多数类基线的准确率就有 0.8 以上，因为大部分评论是 unknown。所以要看 macro-F1。
  3. BoW 好于 GloVe：GloVe 平均把整条评论压成一个向量，「作业不多但考试很难」这种对比就丢了；中文也基本没有向量。
  4. KNN 最差，符合第 3.1 节的预期：高维稀疏向量上的距离意义不大。
  5. 混淆矩阵（例如讲解清晰度）显示，主要错误在「unknown 和有标签之间」以及「mixed」这一类：模型很难判断评论到底有没有谈到某个维度，也很难识别「一半好一半坏」。
- **类别平衡补跑（2026-11-24）**：
  - **原因**：第一次跑时只有 Perceptron 用了类别平衡权重。macro-F1 会奖励照顾少数类的模型，所以对比不公平。
  - **做法**：补跑 `knn_bal` 和 `mlp_bal`，在每个训练折里把每个类别随机过采样到最大类的数量，测试折不动。原来不平衡的 `knn`、`mlp` 结果也保留，用来对照。
  - **macro-F1 平均**（full / level）：

    | 组合 | 不平衡 | 平衡后 |
    |---|---|---|
    | BoW + MLP | 0.30 / 0.35 | **0.34 / 0.40** |
    | GloVe + MLP | 0.26 / 0.32 | **0.33 / 0.38** |
    | BoW + KNN | 0.26 / 0.32 | 0.26 / 0.34 |
    | GloVe + KNN | 0.26 / 0.32 | 0.22 / 0.32 |
    | BoW + Perceptron（本来就平衡） | 0.39 / 0.43 | — |

  - **结论**：
    1. 平衡对 MLP 有明显帮助，说明第一次的差距里确实有一部分来自是否平衡。
    2. 对 KNN 几乎没用。复制样本不会改变近邻的结构，在 GloVe 上甚至更差，因为复制的少数类样本会挤进别人的近邻。
    3. 平衡之后 **BoW + Perceptron 仍然最好**，但领先幅度缩小了：full 任务从领先 0.09 变成 0.05，level 任务从领先 0.08 变成 0.03。24 个「维度 × 任务」组合中，它拿了 19 个第一。
    4. 合理的解释是：只有 3000 条评论，在高维稀疏的 BoW 上，线性模型已经够用；MLP 参数更多，early stopping 又要再分出一部分验证数据，反而吃亏。

### 步骤 5：课程主题

- 主题属于课程层面：用课程名，加上 LLM 从该课全部评论中总结出的关键词
- 主题类别从固定列表中选，可多选，列表见标注指南

### 步骤 6：按「课程 + 老师」汇总

- 每个维度对该组所有评论的标签投票，`unknown` 不参与投票
- 每个结论附上支持条数、冲突条数，以及 1–2 句代表性原文和学期
- 只有 1–2 条有效评论的组合标记为「证据不足」
- 所有维度都没有证据时，结论为 `unknown`

**实现**：[src/aggregate.py](../src/aggregate.py)（2026-11-24 首次运行）
- 输出三个文件：
  - `cleaned/review_instructor_labels.csv`：每条评论 × 每位老师一行，共 3261 行
  - `cleaned/conflicts.csv`：冲突清单
  - `cleaned/course_profiles.csv`：课程 + 老师画像，共 425 个
- **补全缺失老师**：按 `cleaned/review/instructor_fill.csv` 逐条对照，共 52 个名字。规则依次是：
  1. 能唯一对上该课已登记的老师，就用登记名（27 个）
  2. 批次报告里确认过的别名（2 个，如 Alex = LAM Ngok）
  3. 正文给了全名、但不在登记名单里的，新增一位老师（11 个，如 Plato Tse）
  4. 只有名或头衔、对不上或有歧义的，仍记为 Unknown instructor（12 个，如「Henry」同时可能是 CHENG Kam Hang 和 CHANG Henry）
- **同名不同写法**：登记名单里有 9 组明显是同一个人，例如 `CHEUNG, Shing Chi` 和 `CHEUNG, Shing-Chi`、`KAILA, Ilari` 和 `KAILA, Ilari Julius`。2026-11-24 用户确认合并，列表在 `cleaned/review/instructor_name_variants.csv`，脚本读到这个文件就会自动合并。合并后画像从 425 个变为 415 个，冲突从 1216 个变为 1223 个。
- **课程主题**：`cleaned/course_topics.csv`，150 门课。类别由 Claude 根据课名和评论关键词，从固定列表中选取，可多选；关键词取该课评论中出现最多的 8 个。
- **画像中每个维度的取值**（2026-11-24 改为数值，原因见第 5 节）：
  - `{维度}_score`：0–1 的分数，越高表示该属性越强。例如记忆、工作量越高越重，讲解清晰度越高越清楚，评分宽松度越高越松，录播越高越齐全
  - `{维度}_level`：离分数最近的标签，用于展示
  - `{维度}_disputed`：评论之间分歧大时为 True
  - 另附 `{维度}_n`（证据条数）、各标签条数、各学期平均分，以及 2 句原文（多数方和少数方各一句）
- **证据不足**：有效评论少于 3 条的画像标记为 `insufficient_evidence`，共 175 个（合并同名写法后）。
- 「结构化字段」`rating_*`、`has_*` 按组取平均值，作为独立特征保留。
- Unknown instructor 组不做冲突检测，因为组内可能混着好几位老师。

## 5. 冲突处理规则（2026-11-24 已决定：改用数值分数）

**已定原则**：筛选单位是「课程 + 老师」。如果**同一学期、同一课程、同一老师**下，不同学生对同一维度给出不同的判断，**不自动合并**，先汇总报告，由组员一起决定处理方式。

- 冲突定义：同一（学期，课程，老师）组内，某个维度有 ≥ 2 条非 `unknown` 标签且取值不同
- 冲突分级：
  - **相邻冲突**：例如 low 与 medium、clear 与 mixed
  - **相反冲突**：例如 low 与 high、lenient 与 strict、none 与 required
- 输出：`conflicts.csv`，每行列出学期、课程、老师、维度、各方标签和对应原文证据

**最初列出的选项**：取多数票、记为混合、相邻取多数而相反记混合、按证据具体程度加权。

**最终决定（2026-11-24）**：以上都不用。理由是项目最终要给学生推荐课程，需要能排序、能和学生偏好计算距离的数值；一堆 `mixed` 或 `pending_review` 对推荐没有用。具体做法（实现见 [src/aggregate.py](../src/aggregate.py)）：

1. **标签换成分数**：每个标签映射到 0、0.5、1，对应关系见脚本里的 `SCORES`。`conditional_mixed`、`varies` 记 0.5。
2. **收缩平均**：分数 = (各评论分数之和 + K × 先验) / (证据条数 + K)，K = 2。先验是这门课所有老师的平均分，这个平均分本身也向全体平均收缩。这样只有一两条评论时，分数不会被单条评论拉到极端，自然解决了「证据不足」的问题。
3. **分歧作为信息保留**：评论分数的标准差 ≥ 0.35 时，`{维度}_disputed = True`，大致相当于有相当一部分评论给出了相反判断。推荐时可以提示「评价两极，请看原文」，也可以降低这一项的权重。
4. **不分学期，合在一起算**：画像按「课程 + 老师」汇总全部学期；各学期的平均分另列一栏，供需要时参考。
5. **`cleaned/conflicts.csv` 继续生成**，但只用于报告中的数据质量分析，不再逐条裁决。

不同学期之间的差异不算冲突，因为课程设计可能随学期调整。画像里另列各学期的平均分。

**冲突统计（用于报告的数据质量部分）**：
- 共 1216 个冲突（合并同名写法后为 1223 个），涉及 381 个（学期，课程，老师）组。其中相邻冲突 776 个，相反冲突 440 个。
- 最多的几个维度：
  - 工作量 285 个
  - 评分宽松度 212 个，其中相反冲突 110 个
  - 讲解清晰度 223 个
  - 考核难度 173 个
- 冲突主要来自评论多的组。只有 2–3 条标签的冲突里，相反冲突占 24%；超过 10 条标签的冲突里，相反冲突占 69%。
- 1216 个冲突里，646 个最多的那个标签也不超过一半，取多数票时会遇到平票或没有明显多数。
- 改用数值分数后，415 个画像中被标为「分歧大」的维度：评分宽松度 82 个、讲解清晰度 72 个、工作量 63 个、考核难度 51 个，其余维度都在 20 个以内。

## 8. 已知局限（供报告 Section 7 使用）

- LLM 标签不是人工金标准，可能有系统性偏差；通过人工抽检来量化
- 评论存在选择偏差：愿意写评论的往往是体验特别好或特别差的学生
- 旧学期的评论可能已经不反映当前课程设计；画像中保留学期信息
- 评论很少的「课程 + 老师」组合，结论可靠性低，已用「证据不足」标记
- 约 18% 的评论（554 / 3070）缺少老师信息，归入「未知老师」组，无法用于比较老师之间的差异
- 中文评论只占少数，传统模型使用的英文预训练词向量无法表示中文词
- 评论来自公开网站，已删除作者字段；输出中保留的原文证据句可能包含可识别的信息，展示前需要检查

### 全量标注过程记录（2026-11-23 至 11-24）

- **执行**：3040 条评论分成 20 批，由 Claude 子 agent 并行标注；加上试标的 30 条，共 3070 条。
- **中断**：子 agent 两次撞上 5 小时用量上限。第一次中断后从断点继续；第二次中断后，剩下的 531 条由 Codex 标完，Codex 还复核了 4 条子 agent 的标签。
- **串号问题**：第一轮里几个子 agent 共用了同一个临时文件夹，互相覆盖了文件，导致 201 条评论被写进了别的批次。处理办法见 [src/merge_batches.py](../src/merge_batches.py)：每条评论只采用它所属批次自己的标签，混进来的条目一律丢弃，最终每条评论只保留一个标签。
- **标准不一致**：在两边都标过的 22 门课里比较，Codex 的逻辑分析标注率是 66%，子 agent 只有 12%；「有条件或混合」两边分别是 21% 和 7%。原因是 Codex 把课程主题（如「积分」）也当成了证据。处理如下：
  - 逻辑分析：305 个标签里，145 个改为 unknown，13 个调整了等级。
  - 「有条件或混合」：108 个里，66 个改为评论中写明的工作量等级。
  - 覆盖规则保存在 `cleaned/review/overrides_codex_strict.json`，合并时最后应用。
- **重审后**：「有条件或混合」两边都是 7%，已经一致；逻辑分析仍是 30% 对 12%。抽查发现，在明确写了证明、推导、编程作业等要求的评论里，子 agent 只标了 39%，Codex 标了 68%。也就是说，剩下的差距主要是**子 agent 漏标**。
- **第二轮：逻辑分析补标与再核（2026-11-24）**
  - **先把标准写细**：在 `docs/labeling_guide.md` 里给逻辑分析加了一套判定流程。核心是「证据必须说学生要做什么」。以下情况都不算证据，每种有一个原因代码：课程大纲或主题列表、算总评成绩的公式、只列出作业或考试的数量、老师上课自己演示推导、只说「题目很难 / 很刁钻」（这属于考核难度）、只说「要深入理解概念」、花了多少小时（这属于工作量）。
  - **补标子 agent**：用 `src/find_analytical_gaps.py` 按关键词（证明、推导、计算、编程作业、critical thinking 等）筛出 413 条「子 agent 标了 unknown、但正文提到相关要求」的评论，逐条阅读。125 条补上了标签（medium 109、high 15、low 1），288 条仍为 unknown。每一条的结论和原因代码都记在 `cleaned/review/analytical_supplement.jsonl`，接手的人可以直接查。
  - **再核 Codex**：按同一流程复查 Codex 剩下的 160 个逻辑分析标签，43 个改为 unknown（多为老师上课的推导、「题很难」、花费时间），11 个由 high 降为 medium（只说要用逻辑思考、没说难）。
  - **结果**：在两边都标过的课程里按相同课程比较，逻辑分析标注率是 Codex 17.5%、子 agent 16.3%；high / medium / low 的比例也基本一致（5% / 16% / 1% 对 5% / 12% / 2%）。两边标准已经对齐。
  - **覆盖文件的应用顺序**写死在 `src/merge_batches.py` 的 `OVERRIDE_ORDER` 里，文件夹里出现未登记的覆盖文件时合并会直接报错。原来的中间文件 `overrides_analytical.json` 已改名为 `intermediate_analytical.json`，不再参与合并。
- **最终输出**：`cleaned/review_labels.csv` / `.jsonl`，3070 条，校验 0 错误，没有待定条目。

### 试标中发现的数据问题（需留意）

- **老师别名**：评论常用英文名称呼老师。例如「Henry」= `CHENG, Kam Hang`，有评论直接写「鄭錦恒 Kam Hang CHENG（又稱 Henry）」。补老师名时需要一张别名对照表。
- **疑似重名或填错**：MATH1013 中另有一位 `CHANG, Henry`（3 个学期共 5 条评论），其中一条说「Henry is great tutor」。他可能是助教，也可能是老师字段填错了，有待确认。
- **跨老师评价很普遍**：MATH1013 中，LIU Chenkai、HU Zihao、CHIANG Yik Man 等老师名下的评论经常在评价 Henry。这正是规则「只采用字段内老师的证据」要处理的情况。
- **正文老师名不在已知名单里**：例如 Plato Tse 不在 HUMA2921 的已知老师（BROWN Nahum、PROOI Dennis）中。这种情况会按正文新增一位老师。
- **AI 生成的评论**：有评论的 content 部分明显是聊天机器人写的，结尾残留了「要不要我帮你再写一版更简短的选课参考版」。这类内容往往是对课程的泛泛描述，未必来自评论者的亲身经历。是否降低这类评论的权重，待讨论。
